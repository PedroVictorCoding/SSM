# Long-Term Retrieval Memory and User Preferences

This document details the architecture, epistemological classification, access scopes, and ALIGNMENT.md invariant enforcement for the SAIL Long-Term Retrieval and Preferences Memory system (`src/runtime/memory.rs`).

## 1. Overview & Core Motivation

Relying solely on internal model weights or recurrent context windows across conversational sessions causes severe failure modes:
1. **Preference Amnesia or Retraining**: Forcing the model to retrain every time a user configures an editor preference or adds a reference specification is prohibitive.
2. **Epistemological Conflation**: An unverified speculative guess generated by the assistant must never be treated with the same authority as an approved technical specification or verified system fact.
3. **Training Data Contamination (ALIGNMENT.md Violation)**: Speculative model outputs and runtime conversational context must never automatically feed back into training datasets or self-modify model parameters.
4. **Multi-Tenant Leakage**: Private user preferences or session-scoped transient observations must not bleed across unauthenticated sessions.

The SAIL `LongTermMemoryStore` provides host-owned, provenance-tracked, scope-bounded retrieval memory.

---

## 2. Fact Classification & Alignment Boundaries

Every record stored in `LongTermMemoryStore` carries an explicit `FactKind`:

| `FactKind` | Source & Provenance | Verification | Training Eligible? | Typical Retention |
|---|---|---|---|---|
| `ApprovedDocument` | Human-approved documentation, API specs, guidelines | `is_verified: true` | Ineligible at runtime | `Permanent` |
| `UserPreference` | Human user settings (themes, indentation, coding style) | `is_verified: true` | Ineligible at runtime | `Permanent` |
| `VerifiedObservation` | Deterministically executed tool results, confirmed actions | `is_verified: true` | Ineligible at runtime | Configurable / TTL |
| `ModelHypothesis` | Autoregressive model generation or speculative reasoning | `is_verified: false` | **Permanently Ineligible** | `SessionOnly` |

> [!IMPORTANT]
> **Strict ALIGNMENT.md Invariant**:
> Per project guidelines, SAIL must never perform autonomous recursive self-improvement. The `store_model_hypothesis` API guarantees that speculative inferences are flagged as unverified, retained only for the session lifecycle, and rejected if any attempt is made to mark them as training eligible.

---

## 3. Access Scopes and Retention Lifecycle

Access boundaries are enforced on every query via `AccessScope`:
- `AccessScope::Global`: Visible to all sessions and users (e.g. system documentation).
- `AccessScope::User(user_id)`: Visible only to requests authenticated with `user_id`.
- `AccessScope::Session(session_id)`: Isolated strictly to that conversational session.

Retention policies:
- `RetentionPolicy::Permanent`: Preserved until explicit deletion.
- `RetentionPolicy::TtlMs(ttl_ms)`: Automatically purged via `purge_expired` once monotonic age exceeds TTL.
- `RetentionPolicy::SessionOnly`: Cleared upon session conclusion.

---

## 4. Conflict Resolution & Preference Superseding

When a user modifies a preference:
1. The new record is stored with an incremented `version` number.
2. The previous active record has its `provenance.superseded_by` pointer set to the new record ID.
3. Subsequent queries automatically exclude superseded records, returning only the active version.
4. If uncoordinated conflicting records exist for the same topic, they are returned in `conflicts_detected` for transparent resolution.

## 5. Hybrid Retrieval & Bounded Budget Packing

Retrieval combines lexical and semantic relevance:
1. **Lexical (BM25)**: Evaluates term frequency and inverse document frequency with length normalization over an inverted term index:
   $$BM25 = \sum_{w \in Q \cap D} IDF(w) \times \frac{TF(w, D) \times (k_1 + 1)}{TF(w, D) + k_1 \times (1 - b + b \times \frac{|D|}{\text{avg\_doc\_len}})}$$
2. **Semantic (Cosine Similarity)**: Measures angular distance between query embedding and stored document embeddings:
   $$\cos(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}$$
3. **Combined Hybrid Score**: $S = 0.5 \times S_{\text{lex}} + 0.5 \times S_{\text{sem}}$.
4. **Token Budgeting**: Results are greedily packed under `max_tokens_budget` to prevent context window overflow.

## 6. Verification and Benchmarks

The suite in `tests/test_retrieval_memory.rs` validates all acceptance criteria:
- Cross-session retrieval of approved sources with full provenance (`source_id`, `version`, `author`).
- Multi-session and multi-user isolation preventing cross-tenant data leakage.
- User deletion and complete source revocation removing documents immediately from active retrieval and inverted indexes.
- Guaranteed rejection of model hypotheses from training eligibility.
- Sub-millisecond retrieval latency across 100 benchmark documents (<0.1ms).
